## 1. 배경

### 1.1 문제의 규모 (v1에서 유지)

국회 정무위 박성훈 의원이 금융감독원 자료를 분석해 2026년 8월 13일 공개:

| 연도 | 피해액 | 건수 |
|---|---|---|
| 2022 | 1,451억 원 | 28,644 |
| 2023 | 1,965억 원 | 21,401 |
| 2024 | 3,801억 원 | 18,791 |
| 2025 | **8,255억 원** | 33,241 |
| 2026 1Q | 2,259억 원 | 9,788 |
| 합계 | **1조 7,731억 원 / 환급률 22.4%** | 111,865 |

경찰청은 같은 날 딥페이크 AI 3중 대응 체계(2026년 1~7월 419명 검거)의 적용 범위를 **전기통신금융사기로 확대**한다고 발표했다.

### 1.2 그런데 진짜 문제는 따로 있다 — 이 프로젝트의 출발점

한국어 보이스피싱 탐지 연구는 이미 성능 포화 상태로 보고된다.

| 연구 | 데이터 | 보고 성능 |
|---|---|---|
| Mathematics 11(14), 3217 (2023) | KorCCVi v2 | 정확도 99.32%, F1 99.31% |
| Applied Sciences 15(20), 11170 (2025) | 금감원 2,542건 | 텍스트 99.96%, 음성 99.92% |
| arXiv 2506.06180 (Llama3-8B FT) | 자체 수집 | 정확도 100% |

**성능이 99%인데 피해액은 3년 만에 5.7배 늘었다.** 이 모순이 이 프로젝트의 질문이다.

답은 같은 논문 안에 있다.

| arXiv 2506.06180 — KoBERT | 정확도 |
|---|---|
| 정상 테스트셋 | **98.52%** |
| **적대적 테스트셋** | **56.25%** |

문구를 바꾸자 98.52%가 56.25%로 떨어졌다. 이진분류에서 56%는 사실상 무작위다. 같은 조건에서 GPT-4o는 99.11%, Llama3-8B 파인튜닝은 94.64%를 유지했다 — **즉 무너지는 것은 문제의 본질이 아니라 모델 선택과 학습 방식의 문제다.**

음성 쪽도 같다. arXiv 2504.12423은 실제 통신 코덱(AMR-WB, EVS, IVAS, OPUS, Speex, SILK / 8~48kHz / 패킷손실 0~20%)을 통과시키면 기준 모델의 **EER이 평균 5.30%p 증가**함을 보였고, 동시에 **적절한 데이터 증강으로 이 저하를 거의 제거할 수 있음**도 보였다.

> **한 줄 정의:** 보고된 99%는 깨끗한 조건에서만 성립한다. 실제 사기범은 문구를 계속 바꾸고, 통화는 언제나 압축된 8kHz로 들어온다. **이 프로젝트는 그 간극을 측정 가능한 벤치마크로 만들고, 간극을 좁힌 판별기와 이를 상시 감시하는 서빙 파이프라인을 만든다.**

## 2. 문제 정의

### 2.1 세 개의 열화 축

실제 환경과 벤치마크 사이의 간극을 세 축으로 분해하고, 각각을 **코드로 재현 가능하게** 만든다.

| 축 | 무엇이 깨지는가 | 재현 방법 | 근거 |
|---|---|---|---|
| **A. 적대적 문구** | 사기범이 표현을 바꾸면 텍스트 판별기 붕괴 | 규칙 기반 6종 변형 + LLM 패러프레이즈 | KoBERT 98.52% → 56.25% |
| **B. 통신 열화** | 8kHz 압축이 스푸핑 아티팩트를 제거 | ffmpeg 코덱 체인 (G.711 μ-law, AMR-NB, OPUS 저비트레이트, 패킷손실) | 기준 모델 EER +5.30%p |
| **C. 전사 오류** | STT가 깨진 텍스트를 판별기에 넘김 | WER 5/10/20% 오류 주입 시뮬레이션 | 선행 연구 미다룸 (본 프로젝트 기여) |

### 2.2 과제 진술

> **입력:** 통화 오디오 스트림 (또는 전사 텍스트)
> **출력:** 청크 단위 위험 등급(`SAFE`/`WARN`/`BLOCK`) + 판단 근거 + **현재 입력의 열화 수준 추정**
> **핵심 질문:** 열화 조건에서 성능이 얼마나 떨어지는가, 그리고 그 낙폭을 얼마나 줄일 수 있는가
> **최상위 KPI:** **Robustness Gap** = Metric(clean) − Metric(stressed)

### 2.3 왜 판별형 AI인가 (v1 대비 근거 강화)

| 요구사항 | 판별형이 맞는 이유 |
|---|---|
| 실시간 (수백 ms) | 생성형 LLM 호출은 지연·비용 부적합. 경량 분류기는 CPU에서 수십 ms |
| 조건부 확률만 필요 | 결정 경계 P(y\|x)만 있으면 됨. 데이터 분포 모델링 불필요 |
| **임계값 운영** | 미탐 비용(피해 발생) ≫ 오탐 비용(정상 차단). 비대칭 비용을 임계값으로 직접 통제해야 함 |
| **강건성 측정 가능성** | 판별기는 스코어가 스칼라라 열화 축별 성능 곡선을 그릴 수 있음. 생성형은 이 분석이 어려움 |
| 온디바이스 | 통화 내용은 최고 민감 정보. 서버 전송 없이 처리 |

> **참고 — GPT-4o가 99.11%인데 왜 판별형인가:** arXiv 2506.06180에서 GPT-4o가 적대적 조건에서 가장 강했다. 하지만 통화 3초마다 API를 호출하는 것은 지연·비용·프라이버시 모두 불가능하다. **이 프로젝트의 실질적 목표는 "GPT-4o의 강건성에 얼마나 근접한 경량 판별기를 CPU에서 돌릴 수 있는가"이며, 이 비교 자체가 리포트의 핵심 표가 된다.**

## 3. 산출물 구성

### 3.1 KO-VP-Stress — 강건성 스트레스 스위트 (핵심 기여)

데이터셋이 아니라 **변환 코드**로 배포한다. 원본 데이터 재배포 라이선스 문제를 피하면서 누구나 재현할 수 있다.

**축 A. 적대적 문구 변형 (텍스트)**

| 변형 | 예시 방향 |
|---|---|
| A1 동의어·완곡어 치환 | 핵심 어휘를 유사 의미어로 |
| A2 우회 표현 | 직접 지시를 간접 화행으로 |
| A3 표기 교란 | 띄어쓰기 제거/삽입, 자모 분리, 유사 자모 치환 |
| A4 숫자·금액 표기 변형 | 아라비아 숫자 ↔ 한글 수사 ↔ 구어체 |
| A5 화계 변환 | 존댓말/반말/사무체 전환 |
| A6 LLM 패러프레이즈 | 의미 보존 재작성 |

> **윤리 설계:** 새로운 사기 대본을 생성하지 않는다. **이미 라벨이 붙은 기존 공개 데이터의 표면형만 변형**하며, 생성된 변형은 평가 목적으로만 저장소에 포함한다. 변형 규칙은 공개하되 실제 피싱에 쓸 수 있는 신규 시나리오 생성 기능은 넣지 않는다.

**축 B. 통신 열화 (오디오)** — ffmpeg/sox 파이프라인

| 변형 | 설정 |
|---|---|
| B1 대역 축소 | 16kHz → 8kHz 다운샘플 |
| B2 G.711 μ-law | 64kbps, PSTN 표준 |
| B3 AMR-NB | 4.75 / 12.2 kbps |
| B4 OPUS 저비트레이트 | 6 / 12 kbps |
| B5 패킷손실 | 0 / 5 / 10 % |
| B6 배경잡음 | SNR 20 / 10 / 5 dB |

**축 C. 전사 오류 주입 (텍스트)**

| 변형 | 설정 |
|---|---|
| C1 단어 삭제 | WER 5 / 10 / 20% 대응 비율 |
| C2 음성학적 치환 | 유사 발음 어휘 오인식 모사 |
| C3 조사 손실 | 한국어 STT의 대표 오류 유형 |
| C4 숫자 오인식 | 금액·계좌번호 자릿수 오류 |

### 3.2 판별기

| ID | 태스크 | 베이스라인 | 본 모델 | 데이터 |
|---|---|---|---|---|
| D2 | 사기 대화 이진분류 | TF-IDF + LogReg | KLUE-RoBERTa-base (+ 스트레스 증강 학습) | KorCCVi 계열 (~1,377건) |
| D1 | 합성음성 이진분류 | LFCC + LCNN | AASIST-L (+ 코덱 증강 학습) | In-the-Wild (Kaggle) / ASVspoof 2019 LA eval subset |

> **데이터 규모를 숨기지 않는다.** 양성 254건 / 음성 1,123건 수준임을 README에 명시하고, **"이 규모에서 99% 정확도가 나온다는 사실 자체가 태스크가 쉽다는 신호"** 라고 해석을 붙인다. 작은 데이터는 이 프로젝트에서 약점이 아니라 논지의 일부다.

### 3.3 정책 레이어 (v1의 "Fusion" 대체)

**v1의 학습형 융합은 구현 불가로 폐기한다.** 두 판별기의 라벨이 동시에 붙은 샘플이 존재하지 않기 때문이다 (선행 논문도 0.8/0.2로 수동 설정).

대신 **명시적 규칙 정책 레이어**로 재정의하고, 한계를 문서에 정직하게 적는다.

```
risk = policy(s_text, s_audio, degradation_level)

1. 시간 누적:  EWMA(α=0.3)로 청크별 스코어 평활화
2. 열화 인지:  입력 대역폭·SNR 추정 → 신뢰 하락 시 해당 판별기 가중치 자동 감쇠
3. 히스테리시스: WARN 진입 τ_hi, 해제 τ_lo (τ_lo < τ_hi) → 등급 깜빡임 방지
4. 비대칭 비용: 미탐:오탐 = 20:1 가정하에 비용 곡선으로 임계값 결정
```

> **차별점은 2번이다.** "입력이 열화됐다고 판단되면 그 판별기의 발언권을 줄인다"는 규칙은 선행 연구의 고정 가중치(0.8/0.2)가 못 하는 일이고, 스트레스 스위트가 있어야만 검증 가능하다. **벤치마크와 서빙이 서로를 필요로 하는 구조**가 여기서 완성된다.

### 3.4 실시간 게이트웨이

```
WebSocket ──▶ Ring Buffer (3s/1s hop) ──┬──▶ [D1 plugin] ──┐
                                        │                  ├──▶ Policy Layer ──▶ 등급 + 근거
                                        └──▶ STT ──▶ [D2 plugin] ──┘
                                                       │
                                            Redis (세션 상태, TTL 300s)
```

**설계 원칙:** 판별기는 **인터페이스 뒤의 교체 가능한 플러그인**이다. `Detector.predict(chunk) -> score` 계약만 지키면 무엇이든 꽂힌다. 이렇게 하면 모델이 늦어져도 서빙은 Day 2에 완성되고, 더미 판별기로 전체 파이프라인을 먼저 검증할 수 있다.

### 3.5 강건성 회귀 CI (백엔드 포지션 킬러 산출물)

```yaml
# .github/workflows/robustness.yml (개념)
on: [pull_request]
jobs:
  robustness-gate:
    - 스트레스 스위트 전 축 실행
    - 각 축별 성능이 기준선 대비 임계 이상 하락 시 → FAIL
    - PR 코멘트로 축별 성능 델타 표 자동 게시
```

**이 프로젝트에서 가장 드문 산출물이다.** 모델 성능을 CI 게이트로 관리하는 개인 포트폴리오는 흔치 않고, "모델을 서비스로 운영해본 사람"이라는 신호를 가장 강하게 준다.

## 4. 평가 지표

### 4.1 최상위 — Robustness Gap

| 지표 | 기준선 (선행 연구) | v2 목표 |
|---|---|---|
| 텍스트 Gap = Acc(clean) − Acc(적대적) | **42.27%p** (KoBERT 98.52 → 56.25) | **≤ 15%p** |
| 오디오 Gap = EER(코덱) − EER(clean) | **+5.30%p** (기준 모델 평균) | **≤ 2.0%p** |
| 전사오류 Gap = F1(정제전사) − F1(WER 20%) | 선행 미측정 | **측정·보고 (본 프로젝트 최초)** |

> 모든 목표가 **공개된 선행 연구 수치 대비 상대값**이다. "왜 15%p인가"에 "KoBERT가 42.3%p 떨어졌으니 그 3분의 1 이하를 목표로 잡았다"고 답할 수 있다. v1의 임의 숫자와 결정적으로 다른 점이다.

### 4.2 판별 성능

| 지표 | 목표 | 비고 |
|---|---|---|
| D2 clean F1 | ≥ 0.97 | 재현 확인용. 자랑거리가 아님을 README에 명시 |
| D2 adversarial Recall@FPR 1% | ≥ 0.80 | 실질 지표 |
| D1 clean EER | ≤ 10% | 데이터 서브셋 기준 |
| D1 codec EER | ≤ 12% | 열화 후에도 유지 |
| GPT-4o 대비 격차 | 적대적 정확도 격차 ≤ 10%p | 경량 모델의 실용 한계 제시 |

> **Accuracy를 주지표로 쓰지 않는 이유를 README에 별도 섹션으로 적는다.** 양성 254건 / 음성 1,123건에서 전부 음성으로 찍어도 정확도 81.6%가 나온다. 이 계산을 직접 보여주는 것이 실무 감각의 증거다.

### 4.3 서비스 성능

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 판별기 추론 p95 (CPU, ONNX INT8) | ≤ 200ms | pytest-benchmark |
| **엔드투엔드 p95** (오디오 입력 → 등급 반환) | ≤ 1.2s | 실측, STT 포함 |
| 동시 세션 (2 vCPU 단일 컨테이너) | ≥ 10 | Locust |
| 모델 총 용량 | ≤ 150MB | — |
| 콜드 스타트 | ≤ 8초 | — |

> **v1의 "동시 20세션 / p95 300ms"는 STT 비용을 계산에 넣지 않은 숫자였다.** faster-whisper small을 CPU에서 돌리면 3초 오디오 전사에 수백 ms가 걸린다. v2는 실측 가능한 수준으로 하향하고, **"목표를 못 지켰을 때의 트레이드오프 곡선"**(청크 길이 ↔ 지연 ↔ 탐지 성능)을 리포트에 넣는다.

### 4.4 폐기한 지표

| 지표 | 폐기 사유 |
|---|---|
| TTD (Time-to-Detection) | 타임스탬프가 있는 통화 데이터가 존재하지 않음. 자체 합성 시 순환 논리 |
| Fusion 개선폭 +5%p | 두 판별기의 공통 테스트셋이 존재하지 않아 비교 불가 |

> **폐기 사실과 사유를 README에 남긴다.** "측정할 수 없는 지표를 내걸지 않았다"는 것 자체가 판단력의 증거다.

## 10. 즉시 착수할 3가지

1. **Day 1에 모델 없이 돌아가는 시스템을 만든다.** `Detector` 인터페이스와 더미 판별기부터. 모델은 나중에 꽂는다. 이러면 데이터가 안 구해져도 프로젝트가 죽지 않는다.
2. **평가 코드를 모델보다 먼저 쓴다.** Robustness Gap 계산과 데이터 분할(seed 고정)을 Day 3에 확정. 나중에 분할을 바꾸면 모든 숫자가 무의미해진다.
3. **Day 5에 붕괴를 재현하지 못하면 즉시 설계를 바꾼다.** 이 프로젝트의 전제는 "99% 모델이 무너진다"이므로, 그 재현이 Day 5의 유일한 목표다. 재현되면 나머지는 따라온다.
